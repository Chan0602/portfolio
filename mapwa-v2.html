The Product

MAPWA supports the practicum placement process for graduate students, from selecting a placement path through matching and confirmation.

My Role

I led workflow analysis, information architecture, interaction design, prototyping, and the redesign of both student and admin experiences.

Problem

A matching system that worked, but left everyone guessing.

After the first matching round, 43 student emails exposed the same underlying issue: the system completed actions, but rarely told students what happened next—while admins had no single place to understand placement status at a glance.

Reflection

What I took away from this project

Design around decisions, not data

The biggest shift was moving from “How should I display this information?” to “What decision does this help an admin make?”

Not every status needs attention

Normal progress and true exceptions should not compete for the same visual priority. Designing Needs Attention made that distinction explicit.

One system can support different workflows

Students needed a lightweight path to submit and wait, while admins needed dense operational visibility. Shared patterns kept both experiences consistent.

Next step: validate the rules behind the UI

I would test when “Under Process” should become “Delayed,” which capacity signals best predict bottlenecks, and which filtered views admins rely on most.
